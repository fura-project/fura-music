# Maintainer gate: KuGou official-Web Standard candidate

Date: 2026-10-27. **NOT RUN**. This document and tool do not authorize live use.
See the [pinned route decision and HD-031 draft](../research/kugou-authenticated-standard-v1.md).

## Safe preparation (offline, no account)

From the repository root:

```sh
cargo build --offline --locked -p provider-kugou --example kugou_web_playback_gate
python3 scripts/research/test_kugou_web_playback_gate.py
python3 scripts/research/kugou_web_playback_gate.py
```

The last command prints `NOT_RUN` without opening a browser, collecting secrets,
building or issuing requests. The Rust example without its explicit flag also
returns `NOT_RUN`. Do not run the old ignored anonymous probe.

## Separate authority required before the live command

The maintainer must explicitly approve this exact route, use of a disposable
account/session, one selected entitled Standard track and the following budget:

- Human manually opens and logs in at `https://www.kugou.com/` in a **new private
  temporary browser profile**, independent of everyday profiles and Fura's
  QQ/NetEase owners. Login/consent/account confirmation remain Human actions.
  Do not read an ordinary browser Cookie database or Fura vault.
- Zero Fura QR/password/SMS/login/refresh/device registration requests.
- Zero independent Fura account-summary requests: a safe official-Web account
  verification contract has **not** been established. Human confirms the account
  locally; the one songinfo authorization checks only this request's session
  acceptance, not the account's global verified identity. This limitation blocks
  production Authentication/Vault work.
- At most **one** Fura `GET https://wwwapi.kugou.com/play/songinfo`, using the
  exact request generated by that official page for the selected track.
- Optionally, at most **one** `Range: bytes=0-4095` request to one independently
  observed and explicitly approved exact KuGou media hostname. No Cookie/token
  is sent to media. Approve this separately with `--probe-range`.
- No redirect, retry, alternate profile/envelope, additional Search/detail,
  another track, backup source, HTTP downgrade or third-party service.

Do not turn this into an unattended test. A successful third-party README or a
synthetic fixture is not authority to use the maintainer's account.

## Local input prerequisites — do not send these to chat or Git

Use the official site's ordinary Network view **locally**. Do not export a HAR,
“Copy as cURL”, Cookie jar, browser screenshot containing account information,
raw JSON response, full URL or credentials into project logs or chat.

The maintainer must establish:

1. The intended account is logged in and the chosen track has ordinary full
   Standard playback permission on the website. Account mismatch stops here.
2. The exact website request is HTTPS `wwwapi.kugou.com/play/songinfo`, the
   hash/Album profile documented in the research. Its signature, timestamp,
   mid/uuid/dfid are from the actual website session, **not generated by Fura or
   copied from Aerome**. A constructor can check structure, not prove provenance.
3. The minimal `KugooID` and `t` Cookies belong to that same website session and
   equal request userid/token. A KuGoo-only composite or different Cookie names
   do not authorize guessed conversion; this candidate intentionally stops.
4. The selected track's existing exact KuGou context is available:
   `v1:<MixSongID>:<Standard hash>:<Audioid>:<duration seconds>:<Album ID>`.
   This is the existing provider-private format, not a title/artist lookup.
   Missing or contradictory context stops preparation. Do not initiate another
   Fura Search/detail request under this one-request budget to fill a gap.
5. A media host is independently observed and explicitly approved before the
   tool runs. Only that exact lowercase KuGou hostname is accepted. Seeing a new
   hostname in the returned JSON does not authorize broadening the allowlist.

If these materials are unavailable, record the precise missing field/shape and
leave the gate **BLOCKED / NOT RUN**, not a failed live request. If the website
uses only `encode_album_audio_id` or a newer profile, preserve that fact and
stop: music-lib's two-hop route is evidence, not this experiment's one-hop contract.

## Live command — only after that explicit authority

```sh
python3 scripts/research/kugou_web_playback_gate.py --human-authorized-once
```

Only when the optional 4 KiB media budget was also explicitly approved:

```sh
python3 scripts/research/kugou_web_playback_gate.py --human-authorized-once --probe-range
```

The wrapper presents the target/budget and requires the exact authorization
phrase and local account confirmation. It compiles offline before reading
secrets. All sensitive inputs are hidden; unsupported terminal echo control is
a hard failure. Values go only to a bounded stdin pipe, not argv, environment,
files, Cargo logs or a clipboard reader. The capture must still be fresh under
the local 300-second guard. This is not an upstream session-expiry assertion.

The tool sends the original signed query, with honest Fura UA/website
Origin/Referer and minimal Cookie. This differs from reference clients' forged
Chrome UA/full Cookie headers; acceptance is **unproved**, not silently assumed.
Do not change the UA, add hardware fields, re-sign or copy more account context
to work around rejection. Logout/retirement is local and sends no account mutation.

## Stop and output rules

Immediately stop on HTTP 429, CAPTCHA, SSA, verification/secondary confirmation,
unexpected device/signature/private-secret/package/attestation demand, account
mismatch, 403/explicit denial, or unknown access control. Do not generate new
mid/dfid, change profile or restart the tool to bypass the stop.

The Rust owner consumes its attempt **before await**. Error, cancellation,
network failure, session replacement or restaging cannot refund that budget.
No detached request or retry loop exists. Known challenge codes dominate
ordinary error fields and are checked before success data decoding.

Output is fixed categories/booleans only. Successful tool output says
`scope=STANDARD_SOURCE_ONLY`, whether the HTTPS range passed,
`account_summary_verified=false`, `production_enabled=false`. A short prefix
check is not an audible/full-song playback PASS. The tool cannot establish a
region/copyright distinction from an undocumented error code, and reports it
as unclassified/rights denied rather than guessing.

Record only request count, candidate class, credential-kind presence, Human
login/account confirmation, response classification, HTTPS source presence,
range outcome and stop reason. Never record identities, lengths/hashes of
credentials, track/hash/name, full URLs, raw bodies, media bytes or private
browser/Profile paths. Close the disposable browser after the experiment and
remove its explicitly identified temporary profile locally; no profile is
created or deleted by this tool.

Even a PASS leaves production blocked: a separate decision must cover verified
account semantics, independent secure persistence/sign-out/generation,
an ordinarily authorized request-generation contract, Provider MediaResolver,
static routing/capability/Bridge/UI integration and cross-platform playback.
